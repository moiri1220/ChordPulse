# ChordPulse MVP仕様書

## 1. 文書概要

本書は、音源ファイルまたはYouTube URLから楽曲を解析し、ブラウザ上でマスターコード譜を表示・ダウンロードするWebアプリケーション「ChordPulse」のMVP仕様を定義する。今後の設計・実装・受け入れ確認における基準とする。

### 1.1 MVPの目的

- MP3/WAVまたは利用条件を確認したYouTube URLを入力できること
- 音源からBPM、ビート、小節区切り、コード進行を推定できること
- 推定結果をコードネーム付きのリズムスラッシュ譜としてMusicXMLに変換できること
- MusicXMLをブラウザ上で表示し、ファイルとしてダウンロードできること

### 1.2 MVPの前提と制約

- 解析結果は音源からの推定値であり、完全な正確性を保証しない。
- 対象は主にコード伴奏を含む楽曲とする。複雑な転調、ポリコード、無拍子、極端なライブ録音などは精度低下の可能性がある。
- 初期版では、譜面の手動編集、元音源との同期再生、ユーザーアカウント、保存・共有機能は対象外とする。
- YouTube URLの利用は、権利・利用規約・取得方法を確認したうえで、設定により有効化する。

### 1.3 音源の利用方針

本アプリは、音源を鑑賞・再配信することではなく、コード、BPM、拍位置、リズムなどを抽出する情報解析として利用することを基本とする。日本の著作権法第30条の4の適用が想定されるが、必要な限度を超える利用、著作権者の利益を不当に害する利用、その他の法令・契約・規約に反する利用を認めるものではない。

#### 基本ルール

- 利用者は、適法に入手・利用できる音源だけをアップロードまたはURL入力する。
- 違法にアップロードされた音源であると知りながら取得・解析すること、アクセス制限やコピー防止を回避することは禁止する。
- 利用者の確認だけで法的適法性を保証できるわけではないため、疑わしい音源や権利者から停止要請を受けた音源は処理しない。
- 解析中の音源は一時ファイルとして扱い、MusicXML生成後またはエラー時に直ちに削除する。削除漏れに備え、短時間の有効期限を持つクリーンアップ処理を設ける。
- 音源の永続保存、ユーザー間共有、公開URL化、音源の再ダウンロード機能はMVPに設けない。
- 出力はコードネーム、BPM、拍子、リズムスラッシュ等のマスターコード譜に限定し、音源、歌詞、メロディー、長い音声断片を含めない。
- MusicXMLの公開・商用利用など、解析後の利用については利用者が別途確認する。サービスは出力の利用許諾を保証しない。

#### YouTubeの取り扱い

- YouTube URLを使う場合は、利用者が規約・権利条件を確認したことに同意するチェックを設ける。
- `yt-dlp`等で違法アップロードと知りながら取得すること、DRM・アクセス制限・コピー防止を回避することは禁止する。
- YouTubeの利用規約がダウンロードを許可していない場合は、そのURLを処理しない。YouTubeの規約変更時は機能の有効・無効を見直す。
- YouTube URLから取得した音源も、アップロード音源と同じく解析中だけ保持し、解析完了後に削除する。
- YouTubeの仕様上、公式に許可された埋め込み視聴と音声ダウンロードは別の扱いであるため、取得方法を実装する前に確認する。

権利侵害の申告や削除依頼を受けた場合は対象処理を停止し、音源・中間データ・生成物を速やかに削除する。判断に迷う場合は処理を停止し、運用責任者または法律専門家へ確認する。

## 2. システム概要

音源ファイル（MP3/WAV）または利用条件を確認したYouTube URLを入力として受け取り、音声取得・音楽解析・MusicXML生成を行う。音源は解析中のみ保持し、生成したMusicXMLをフロントエンドへ返却して、OpenSheetMusicDisplay（OSMD）でマスターコード譜を描画する。

```text
[MP3/WAV または 利用条件確認済みYouTube URL]
                |
                v
        [音源の取得・WAV化]
                |
       +--------+---------+
       |                  |
       v                  v
[BPM/ビート解析]     [コード解析]
  librosa          Chordino / madmom
       |                  |
       +--------+---------+
                v
       [拍・小節・コードの統合]
                |
                v
        [music21でMusicXML生成]
                |
       +--------+---------+
       |                  |
       v                  v
 [OSMDで表示]       [.musicxmlダウンロード]
```

## 3. 想定ユーザーフロー

1. 利用者がMP3/WAVを選択する、またはYouTube URLを入力する。
2. 利用条件と権利を確認したことに同意する。
3. リズム表記レベル（レベル1〜3）を選択する。
4. 「解析」を実行する。条件に反する入力は音源取得前に拒否する。
5. バックエンドが音源を一時領域で正規化し、BPM・ビート・コードを解析する。
6. 解析結果からMusicXMLを生成し、音源を削除する。
7. フロントエンドが譜面を表示し、利用者がMusicXMLをダウンロードする。

## 4. 機能仕様

### 4.1 入力

| 入力 | MVP仕様 |
| --- | --- |
| 音源ファイル | MP3/WAVを受け付ける。利用者が適法に利用できる音源であることを確認する |
| 利用条件確認 | 解析前に、違法入手・違法アップロード音源を扱わないことへの同意を必須とする |
| YouTube URL | 利用規約・権利条件・取得方法が許される場合に限り受け付ける。設定で無効化可能とする |
| 表記レベル | レベル1、レベル2、レベル3から1つ選択する |
| 同時指定 | 音源ファイルとURLの同時指定は不可 |

入力形式、拡張子、URL形式、ファイルサイズ、利用条件確認、サービス設定などのバリデーションを行う。不正な入力、明らかに違法な入力、利用条件に反する入力は解析開始前に拒否する。

### 4.2 音源取得・前処理

- ローカルファイルはバックエンドで読み込み、解析に適した音声形式へ正規化する。
- YouTube URLを有効化する場合は、取得方法がYouTubeの規約・APIポリシーと利用条件に適合することを確認する。`yt-dlp`が常に利用可能であるとはみなさない。
- 解析処理は入力音源を隔離された一時領域に保存して実行し、解析完了・失敗・キャンセル時に不要な一時ファイルを削除する。
- プロセス異常終了に備え、短い有効期限を持つクリーンアップ処理を起動時および定期的に実行する。
- 音源本体や音声断片をログ、エラー通知、外部分析サービスへ送信しない。
- 取得失敗、対応外形式、破損ファイル、長すぎる音源はエラーとして扱う。

### 4.3 BPM・ビート・小節解析

`librosa`を使用し、以下を推定する。

- 楽曲の推定BPM
- 拍の発生時刻
- 拍を基準とした小節区切り
- コードを配置するための拍位置・小節位置

拍子はMVPでは基本的な4/4拍子を優先する。拍子推定を導入する場合も、MusicXMLに確実に反映できない場合は4/4拍子へフォールバックする。

### 4.4 コード解析

`Chordino`（Vamp Plugin）または`madmom`を候補エンジンとして使用し、時間区間ごとのコードネームを推定する。

- 推定されたコード区間をビート位置へ量子化する。
- 隣接する同一コード区間は統合する。
- コードの切り替えが拍の途中にある場合は、利用中の表記レベルに応じた最小単位へ丸める。
- コードを判定できない区間は、無理にコードを補完せず、休符・空欄・直前コードの保持などのルールを実装時に選択する。
- 出力するコードネームの表記規則（例：`C`, `Am7`, `G7`）を全解析で統一する。

解析エンジンは交換可能な構造とし、初期実装でChordinoまたはmadmomのどちらかを採用しても、将来別エンジンへ差し替えられるようにする。

### 4.5 適応型リズム記譜（Adaptive Rhythm Notation）

原曲のコードチェンジのタイミングと持続長に応じて、最適な音価（全音符・2分音符・4分音符・付点音符・8分音符等）を持つリズムスラッシュ音符およびコード記号を小節内に自動配置する。

- **小節全体で同一コード**: 全音符（4拍）× 1
- **2拍ごとに変化**: 2分音符（2拍）× 2
- **1拍ごとに変化**: 4分音符（1拍）× 4
- **シンコペーション（例: 1.5拍/2.5拍）**: 付点4分音符（1.5拍）＋ 8分音符等
- **無音・未判定区間**: 休符（Rest）を配置

### 4.6 MusicXML生成

`music21`を使用してMusicXMLを生成する。

- 拍子、推定BPM、拍・小節構造を設定する。
- コードネームをコードシンボルとして配置する。
- 指定レベルに応じたリズムスラッシュを配置する。
- 楽器パートはマスターコード譜向けの単一パートを基本とする。
- ダウンロード可能な`.musicxml`ファイルとして出力する。
- 生成物はOSMDで読み込めるMusicXMLであることを満たす。

### 4.7 譜面表示

フロントエンドではOpenSheetMusicDisplay（OSMD）へ生成したMusicXMLを渡し、ブラウザ上に描画する。

- コードネームとリズムスラッシュを表示する。
- 解析中は処理状態を表示する。
- 成功時は譜面表示とMusicXMLダウンロード操作を表示する。
- 失敗時は原因が分かるメッセージを表示する。

## 5. 画面仕様（MVP）

### 5.1 解析画面

- アプリケーション名・説明
- 音源ファイル選択欄
- YouTube URL入力欄
- 利用条件・権利を確認したことを示すチェックボックス
- リズム表記レベル選択欄
- 解析開始ボタン
- 入力エラー、解析中、解析失敗の状態表示
- YouTube入力が設定で無効な場合は、その旨を表示

### 5.2 結果画面

- 推定BPMの表示
- 生成されたマスターコード譜の表示
- MusicXMLダウンロードボタン
- 新しい解析を開始する操作

## 6. 技術構成

| 層 | 採用技術・候補 | 役割 |
| --- | --- | --- |
| フロントエンド | Next.js または Nuxt.js | 入力UI、解析状態管理、結果表示 |
| 譜面描画 | OpenSheetMusicDisplay | MusicXMLのブラウザ描画 |
| バックエンド | Python / FastAPI | 入力受付、解析実行、MusicXML返却 |
| 音源取得 | ローカルファイル処理 / `yt-dlp` | 音源を解析中だけ一時的に取得。YouTube利用時は規約・権利条件を確認 |
| BPM・ビート解析 | librosa | BPM、拍、オンセットの推定 |
| コード解析 | Chordino（Vamp Plugin）または madmom | コードネームの推定 |
| 楽譜生成 | music21 | リズムスラッシュ・コードシンボル付きMusicXMLの生成 |

フロントエンドはNext.jsまたはNuxt.jsのいずれかをPhase 2開始時に確定する。バックエンドとの通信契約は、フロントエンドの選択に依存しないHTTP APIとして定義する。

## 7. API仕様（MVP案）

### `POST /analyze`

音源ファイルまたは条件を満たすYouTube URLを解析し、MusicXMLを利用者だけに一時返却する。

#### リクエスト

`multipart/form-data`を基本とする。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `file` | File | 条件付き | MP3/WAV。URL指定時は不要 |
| `youtube_url` | string | 条件付き | 利用条件を確認したYouTube URL。ファイル指定時は不要 |
| `lawful_use_confirmation` | boolean | Yes | 違法入手・違法アップロード音源を扱わないことへの同意。`true`以外は拒否 |
| `rhythm_level` | integer | Yes | `1`、`2`、`3`のいずれか |

`file`と`youtube_url`は一方のみ必須とする。YouTube入力を設定で無効化している場合や、利用規約・権利条件を満たさない場合は、音源を取得せず拒否する。

#### 成功レスポンス

- Content-Type: `application/vnd.recordare.musicxml+xml` または `application/xml`
- Body: 生成されたMusicXML
- レスポンスは解析を依頼した利用者の一時取得に限定し、サーバー上の公開保存や共有リンクを作成しない
- 推定BPMなどのメタデータは、レスポンスヘッダーまたはJSONラッパー形式の採用を実装時に確定する

MVPでは譜面生成を確認しやすくするため、API契約の初期実装はMusicXML本体の返却を優先する。BPMを画面に表示する必要があるため、実装時には`metadata`とMusicXMLを分離して返すJSON形式、または別メタデータAPIを選択する。

#### エラー

| HTTPステータス | 用途 |
| --- | --- |
| 400 | 入力不足、入力形式不正、リズムレベル不正 |
| 403 | 利用条件に反する入力、YouTube URL機能の無効化、取得許可のないURL |
| 413 | ファイルサイズまたは音源長が上限超過 |
| 422 | 解析できない音源・URL |
| 500 | 解析エンジンまたはMusicXML生成の予期せぬ失敗 |

エラー本文は、フロントエンドが利用者向けメッセージを表示できるJSON形式とする。

## 8. 非機能要件（MVP）

- 解析中に二重送信を防止する。
- 解析失敗時、成功時、キャンセル時のいずれも音源・中間音声を残さない。
- 音源の一時保持は解析中に限定し、解析完了・失敗・キャンセル時に削除する。起動時・定期処理で期限切れファイルを削除する。
- 音源本体、音声断片、未加工のYouTube URLをログ・外部分析サービスへ送信しない。
- 解析結果とMusicXMLを公開保存せず、第三者と共有できる機能を設けない。
- APIキーなどの秘密情報をクライアントへ露出しない。
- 生成したMusicXMLがOSMDで読み込めることを自動確認するテストを用意する。
- 違法アップロードと知りながら取得する入力、コピー防止やアクセス制限を回避する入力を処理しない。
- YouTube URL機能は設定で無効化でき、規約・APIポリシー・取得方法に問題がある場合は無効化する。
- 解析処理が長時間化する場合に備え、将来的に非同期ジョブへ移行できるよう解析ロジックをAPI層から分離する。

## 9. MVPの受け入れ条件

- MP3またはWAVを入力して解析を開始できる。
- 利用条件確認に同意した音源だけが解析される。
- 違法入手・違法アップロードと知りながらの入力、利用条件に反するYouTube URL、設定で無効化されたURLは、音源取得前に拒否される。
- BPMとビート位置が推定され、譜面の小節構造に反映される。
- コードネームが推定され、コード切り替え位置に表示される。
- レベル1〜3の指定がMusicXMLのリズム表記へ反映される。
- 生成されたMusicXMLがブラウザ上でOSMDにより表示される。
- MusicXMLをダウンロードでき、再利用可能なファイルとして開ける。
- 不正入力、取得失敗、解析失敗を画面上で判別できる。
- 処理終了後に音源と中間音声が削除され、音源本体がログや公開領域に残らない。
